# OpenAPI contract vs local runtime

Comparison for [`openapi.yaml`](../../openapi/openapi.yaml), built from the five operations in [`inventory.md`](inventory.md). The comparison used the running local Indico v3.3.14 stack at `http://localhost:8081` on 2026-11-27. These are observed local results; they are not claims about every Indico deployment or configuration.

The spec intentionally preserves the source and inventory contract where runtime behavior differs. None of the mismatches below was hidden by changing the spec to match a failure.

## Mismatches

|---|---|---|---|

A timestamp with `Z` returned HTTP 500, `AssertionError: expected naive datetime`. Timeline and booking response start/end values are also serialized without offsets. | Inputs use `fields.DateTime` in `indico/modules/rb/controllers/backend/bookings.py:64-66` and `indico/modules/rb/schemas.py:411-412`. | `POST /rooms/api/booking/create`: `reason` | Optional request field with source default `""`. | In this seeded local configuration, omitting `reason` returned HTTP 422 with `Booking reason not specified`; a valid non-empty reason returned HTTP 200. ## Confirmed response representation

The error body depends on request headers/content type. The inventory's authenticated API calls sent `X-Requested-With: XMLHttpRequest` and received JSON errors. Fresh GET requests without that header returned `text/html; charset=utf-8` Indico pages for both a 404 and a 422. The spec describes both JSON and HTML error representations; send `X-Requested-With: XMLHttpRequest` when a structured JSON error body is needed. The HTML evidence omits transient CSRF values and CSP nonces.

Evidence: [`error representation checks`](evidence/error-representation-live.txt), [`JSON 404`](evidence/booking-detail-missing-user1.txt), and [`JSON 403`](evidence/room-timeline-anonymous.txt).

## Scope and validation

The OpenAPI document has exactly five path/method pairs, matching the operations in the inventory. It excludes the separate `GET /rooms/api/timeline` route because the inventory covers only the multi-room `POST` used by the workflow.

Validation command: `python -m openapi_spec_validator openapi/openapi.yaml` using `openapi-spec-validator` 0.9.0. Output: `openapi/openapi.yaml: OK`. The validator output and exact path list are in [`openapi-spec-validator.txt`](evidence/openapi-spec-validator.txt).
